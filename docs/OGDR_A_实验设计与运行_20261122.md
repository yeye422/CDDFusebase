# OGDR-A：光学结构引导的动态 Detail 重建（QXS-SAROPT）

状态：**已实现训练、评估与单元测试入口；尚未在本地 QXS / CUDA 上执行，所有性能均待验证。**
基线：`OpticalBaseAnchoredE2`，原 4 轮重建 + 12 轮融合、seed42、原强度/梯度融合损失。

## 1. 实际实现与预期设计的区别

保留原 `MultiScaleDetailFusion(64,32,16)`、光学 Base 直连、LWPD-E2 和原 Decoder。
在融合器输出的 64 通道 `D_f` 后，增加 4 组、每组共享 3×3 核的局部差分算子：

```text
Optical/SAR -> Shared Encoder + LWPD E2 -> optical Base + SAR correction -> B_f
                                      \-> original Detail fusion ----------> D_f
Optical Detail D_o --(abs activity -> smooth -> Sobel)--> optical guide
[D_f, B_f, D_o, optical guide] -> grouped dynamic 3x3 kernel + gate
D_f' = D_f + 0.10 * tanh(1x1(local_difference(D_f, dynamic_kernel)))
[B_f, D_f'] -> unchanged Decoder -> image
```

**注意：** 为保持原 `fuse_features` 与两阶段训练接口，首版的结构条件取自
`D_o` 的通道绝对值活动图，先取绝对值、再平滑并做 Sobel，而**不是原始光学灰度图的 Sobel**。
这是 feature-guided OGDR-A；后续若需要原图梯度输入，应单独定义新版本并作公平对照。
这里没有人工结构真值、噪声概率或 SAR 物理域建模。

具体算子：`K_g(p,q)=softmax(MLP(context))`，`g=1..4`，`q` 为 3×3 邻域；
`R_g(p)=sum_q K_g(p,q)[D_{f,g}(p+q)-D_{f,g}(p)]`。
所有通道保留原位特征；局部常值输入时差分为零。
最后一层 1×1 权重严格零初始化，故训练前 `D_f'=D_f`；
`tanh` 把每元素修正幅度限制在 0.10 个特征值单位，而非限定视觉伪影。

## 2. 四个独立的从头训练变体

| `--mode` | 具体定义 | 用途 |
|---|---|---|
| `conv` | 全图共享的可学习 3×3 分组核 | 位置不变局部算子对照 |
| `dynamic` | 由 `D_f,B_f` 预测逐位置核，不读取额外 `D_o` 条件 | 动态核对照 |
| `guided` | `D_f,B_f,D_o` 和对齐光学结构证据预测核 | OGDR-A 主方案 |
| `shifted` | 和 `guided` 相同架构，但光学证据/投影循环错位半幅 | 空间条件对照 |

四个变体参数张量形状一致，但 `conv`、`dynamic` 中有条件分支不参与梯度，
因此**不能称为严格匹配的有效参数量对照**；研究结论应结合分支激活情况解释。
`guided` 和 `shifted` 的有效结构相同。
此外，同权重 `off` 可关闭新增残差；`guided` 同权重还可对照 `shifted`，
这只检验推理时条件作用，不等同于独立训练。

## 3. 本地 Windows CMD 命令

先从仓库根目录执行：

```bat
cd /d "D:\#imageInfusion\CDDFuse"
git pull --ff-only origin main
.venv\Scripts\python.exe -m unittest discover -s tests -p test_e2_ogdr.py -v
.venv\Scripts\python.exe run_e2_ogdr.py smoke --mode guided
.venv\Scripts\python.exe run_e2_ogdr.py check --mode guided --scale pilot
```

`smoke` 用合成张量做前向/反向，**不需要 QXS 数据，也不写权重**。
`check` 要求本地已经具有之前的 `ORIGINAL_LOSS_PILOT` 权重及归档 val64 结果，
并核对 train1024/val64 划分、训练配置和评价口径。

小试阶段建议先单独跑主方案：

```bat
.venv\Scripts\python.exe run_e2_ogdr.py train-val --mode guided --scale pilot
```

其他三个独立对照（每条都需要完整训练）：

```bat
.venv\Scripts\python.exe run_e2_ogdr.py train-val --mode conv --scale pilot
.venv\Scripts\python.exe run_e2_ogdr.py train-val --mode dynamic --scale pilot
.venv\Scripts\python.exe run_e2_ogdr.py train-val --mode shifted --scale pilot
```

如果意外中断且已经生成可用断点，按模式续训并验证：

```bat
.venv\Scripts\python.exe run_e2_ogdr.py resume --mode guided --scale pilot
```

只评估已完成的权重：

```bat
.venv\Scripts\python.exe run_e2_ogdr.py val --mode guided --scale pilot
```

独立的 train8000/val1000 正式确认仅在小试有效后执行：

```bat
.venv\Scripts\python.exe run_e2_ogdr.py check --mode guided --scale full
.venv\Scripts\python.exe run_e2_ogdr.py train-val --mode guided --scale full
```

`full` 要求本地有既有 `BASE_ANCHOR` 权重、归档的同协议 E2 val1000 和原始切分。
训练要求 CUDA 可用；模型实现本身不依赖自定义 CUDA 核。使用既有
`test_OS.py` 也能评估完成的权重：

```bat
.venv\Scripts\python.exe test_OS.py --data-root ..\datasets\QXSLAB_SAROPT --split val --split-manifest models\e2_ogdr_guided_pilot_v1\seed42\pilot_manifest.json --variant auto --checkpoint models\e2_ogdr_guided_pilot_v1\seed42\epoch_016.pth --output-dir test_result\e2_ogdr_guided_pilot_direct --metric-profile reference_v2_candidate_with_paper_fmi --output-range-policy clamp --limit 64
```

优先使用 `run_e2_ogdr.py val`，因为它还会进行归档 E2 的配对检查。

## 4. 结果位置与筛选

- 小试：`test_result/e2_ogdr_<mode>_pilot_v1/val64/seed42/paired_comparison.csv`
- 完整：`test_result/e2_ogdr_<mode>_full_v1/val1000/seed42/paired_comparison.csv`
- 每个条件包含 `metrics.csv`、`gray/`；新增修正条件含 `diagnostics.csv`。
- 训练：`models/e2_ogdr_<mode>_<scale>_v1/seed42/history.csv` 和 `epoch_016.pth`。

按 `reference_v2_candidate_with_paper_fmi`、`clamp_then_uint8` 评估，
对相同场景的有限值计算指标差异与 bootstrap 区间。NAB/F 越低越好，
FMI、QAB/F、VIF、SSIM 等越高越好；不能将旧 `paper` 评估口径混入比较。

**通过标准：** `guided` 相比匹配 E2 至少有较稳定的综合收益且 NAB/F 不劣化；
`guided` 相比 `conv`、`dynamic` 和 `shifted` 有可解释增益；
同权重 `off` 可检测实际改变量。若 `guided` 仅出现 AG/SF 上升、NAB/F 明显恶化，
则停止扩到完整训练。本文不承诺任何尚未测出的指标收益。
