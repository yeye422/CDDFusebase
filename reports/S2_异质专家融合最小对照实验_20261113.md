# S2 异质专家融合：第二阶段最小匹配实验

状态：**代码已提交，尚未执行真实数据训练。** 本实验只使用 QXS-SAROPT 的 train/val，不使用 test。

## 为什么做

2026-11-13 冻结 E2 的 64 个区域诊断证明存在明显模态响应差异，但强相关主要来自场景与 Detail 幅值。这**不能**证明区域选择三个专家优于普通卷积。

下一阶段独立检验三个因素：固定卷积的容量、异质融合算子的增益、Top-2 稀疏选择的独立增益。

## 四组匹配方案

| 模式 | Detail Fusion | 初始化 |
|---|---|---|
| e2_ft | 原 E2 MultiScaleDetailFusion | 原 checkpoint |
| conv | 约同参数量的普通卷积融合 | 随机初始化 + 原 E2 Detail 特征模仿 |
| dense | 光学方向/SAR 上下文/局部协作三专家；3路 Softmax | 随机初始化 + 相同模仿 |
| top2 | 与 dense **完全相同**的专家及 Router；每个16×16特征块选2个专家 | 随机初始化 + 相同模仿 |

以当前代码的算子参数量计：conv **106008**，dense/top2 **103147**，差异约2.77%。不含共享 E2 编码器、LWPD、Base Fusion、Decoder。

**注意：**Top-2 仍是专家间归一化竞争，并非数学上非零和；首版仍计算全部三个专家，不宣称稀疏推理加速。

冻结 Encoder、LWPD、Base Fusion；Detail Fusion 使用1e-4，Decoder 使用1e-5。沿用原 E2 融合损失 `L_I + 10L_G + 0.1L_R`。所有四组使用 seed42、相同 train1024 / val64、batch2 / 累积4、融合训练3轮。新头先执行64个 batch 的原 E2 **Detail特征模仿预热**（Top-2 预热期间使用 dense，确保三专家获得梯度）；e2_ft 没有额外预热更新。因此重点是 **conv vs dense vs top2**，不能把 e2_ft 对照当作严格相同总优化计算量。

验证集为原 manifest **前64张**，与此前均匀采样 val64 pilot 不同，不应跨 pilot 直接比较。

## 结果解释

- **conv ≈ dense ≈ top2**：不支持异质专家与路由必要性。
- **dense > conv、top2 ≈ dense**：支持异质算子但不支持 Top-2。
- **top2 > dense > conv**：支持继续 S2；还须核查路由与专家输出差异、不同种子，以及 full val1000。
- 如果路由均衡但专家输出高度相似，专家行为仍未分化。
- 如果 NAB/F 显著恶化，不能单凭 SSIM 改善判定通过。
- 无法由此证明某个专家在某区域是“正确”的真实结构专家。

现阶段不训练整套大型 S2，不改 LWPD，不引入 DINO / 预训练教师，也不增加新的融合评价指标。四组通过后再做扩大数据规模和多种子验证。
