# Detail 多尺度融合相对原版 INN 的证据复核

日期：2026-11-19。本轮仅读取已有模型配置、验证元数据和逐图指标，未训练、未推理、未重新评测数据集。以下数值是对已有 CSV 的描述性汇总，不是新增实验结果。

**结论：目前没有证据证明“仅把原版 INN Detail 融合换为多尺度卷积”带来了稳定的独立收益。早期完整 R3 有 QAB/F 均值提升，但伴随其他指标代价；后续 LWPD-E2 的整体收益不能归给多尺度头。**

**已有对照具体比较了什么。**

- R0：原 Base 融合、先相加再 INN 的 Detail 融合，保留图像输入旁路。
- R1：与 R0 使用相同融合结构，取消图像输入旁路，直接解码。
- R2：Base 和 Detail 都换成双源 concat-conv，直接解码，融合总参数量接近 R3。
- R3：Base 换成跨模态通道交互，Detail 换成多尺度卷积联合聚合，直接解码。

因此，R0→R3 同时涉及两类融合及图像旁路；R1→R3 仍同时涉及 Base 与 Detail 两部分，不能隔离 Detail 多尺度模块。R2→R3 也不是单独的多尺度消融。

实现依据：[模型构造](../direct_fusion.py)、[原始改造方案及控制矩阵](../docs/history/CDDFuse直接融合架构改造方案_20261023.md)。原方案已明确提出后续需要 Base/Detail 单独替换消融，本次查到的 R0–R3 产物本身不包含这两个独立替换组。

**早期完整 R3 没有全面优于保留原 INN 的 R1。**

检查目录 `test_result/direct_fusion_qxs/qxs_direct_seed42_v1/val_extended/`。R0–R3 的配置均为 seed42、同一初始 Encoder/Decoder checkpoint 哈希、T0=1、T1=8、相同原损失系数与数据子集哈希。epoch9 验证均为同顺序 val1000、offset0、旧 `paper` 指标、clamp 输出。

但注册表当前只查到 R3 epoch9 作为后续 LWPD 的参照条目，没有完整同组 R0/R1/R2 登记，因此下述是历史探索性复核，不整理为正式注册组排名表，也不与现行 reference 指标混用。各指标按双方共同有限的逐图值汇总，以下均为 n=1000。

固定 epoch9，R1→R3：

- QAB/F：0.718365→0.722255，均值增加 **0.54%**；逐图仅 **372/1000** 提高，不能称为大多数场景改善。
- NAB/F：0.079696→0.108378，**恶化 35.99%**，越低越好。
- FMI：0.726323→0.703281，下降 **3.17%**。
- VIF：0.403211→0.392720，下降 **2.60%**。
- SSIM：0.535087→0.532490，下降 **0.49%**。
- SCD：1.255369→1.190529，下降 **5.16%**。
- MS-SSIM：0.568619→0.568027，下降 **0.10%**。

这不是只挑末轮否定 R3：在 epoch7，R3 的 NAB/F 相对同轮 R1 降低 40.66%，QAB/F、FMI、SSIM 均值也提高，但 VIF、SCD、MS-SSIM 下降；epoch8 的 NAB/F 又相对恶化 9.63%。不同训练轮次的取舍明显变化，不能从中挑一个有利指标/轮次宣称稳定联合收益。

来源：[已保存总表](../test_result/direct_fusion_qxs/qxs_direct_seed42_v1/val_extended/summary.csv)、[R1 epoch9 逐图指标](../test_result/direct_fusion_qxs/qxs_direct_seed42_v1/val_extended/r1_epoch_009/metrics.csv)、[R3 epoch9 逐图指标](../test_result/direct_fusion_qxs/qxs_direct_seed42_v1/val_extended/r3_epoch_009/metrics.csv)。数值来自原始逐图记录，百分比为两组共同有限样本均值的相对变化，未进行训练种子显著性推断。

R2 在该预算下出现严重退化，例如 epoch9 的 FMI≈0.214、VIF≈0.00494、SSIM≈−0.274。因此，R3 胜过这个 R2 不能单独证明多尺度机制成立；其中还涉及 Base 结构及优化成功与否。

此外，配置记录中 R1 的 Detail 融合为 18,176 参数，R3 为 61,616 参数；即使 R3 整网因 Base 改动而更小，也不能说 Detail 头本身是等容量替换。现有结果不足以把尺度、来源输入方式、Base 条件及容量因素分别归因。

**LWPD-E2 的收益不能反推多尺度头优于 INN。**

R3 已经使用多尺度 Detail 头；后续 LWPD-E2 在这套融合基础上改变分解与方向调制，并使用了额外初始化/训练流程。因此，E2 相对 R3 或旧 B0 的改善是相应完整版本的证据，不是 INN 与多尺度卷积的单变量比较。

同时，不能从本次复核推出“恢复原 INN 一定更好”。R1 与 LWPD-E2 的输入分布、Base 表示及训练背景不同，移回 INN 后需要重新适应。

**最小缺失对照。**

若后续决定补证据，保持同一个 LWPD-E2 的 Encoder、Base 结构、Decoder、原损失、manifest、初始化规则和训练预算，只比较 Detail 融合头：

- A：原式两源相加 + INN。
- B：来源分别输入的单尺度卷积头。
- C：当前多尺度卷积头。

A→C 检验整个 Detail 头替换是否有实际收益；B→C 在匹配有效参数和计算预算的前提下检验多尺度的额外贡献。A→B 同时改变算子与来源处理，不将其差值单独称为来源保留收益。现有适用 C 对照继续复用，不默认重训；缺失 A/B 才另列新增成本。完整新模型默认从头初始化，历史冻结诊断与权重迁移不替代训练消融。

当前应采用的表述是：**多尺度 Detail 融合是现有 E2 组合架构的一部分，其独立优越性尚未建立。不能据此认定现有多尺度头已优于原 INN，也不能认定换回 INN 会改善当前问题。**

本轮未生成新融合图或评价结果，不修改实验注册表，不自动运行旧训练脚本。未来新增评价沿用 `reference_v2_candidate_with_paper_fmi`，使用唯一输出目录并按同组规则登记。
