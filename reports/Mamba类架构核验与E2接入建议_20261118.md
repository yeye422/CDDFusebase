# Mamba 类架构核验与 E2 接入建议

核验日期：2026-11-18。范围：用户粘贴材料涉及的原始论文、作者实现，以及当前 CDDFuse 的 E2 代码和已有结果。本轮仅读取文献、代码、已保存 JSON 与环境包元数据，没有训练、模型推理、批量测试或依赖安装。

**结论：材料中的主要论文真实存在，GDN2 可以保留为优先研究的递归候选；但“它最适合修复当前 E2”仍是待验证判断。现阶段更合理的目标是验证源别分账的增量记忆是否改善最终结构传递，而不是把 E2 的退化解释为已经证实的记忆覆盖。EDA、KLA 暂不进入首轮实现。**

这里的优先级属于结合当前项目的研究判断，不是原论文给出的光学—SAR 融合排名，也不代表对截至当日全部递归架构的穷尽调研。

**当前 E2 支持的事实，与材料中的因果假设存在距离。**

`direct_fusion.py` 的 `MultiScaleDetailFusion` 先分别投影 Optical/SAR，再拼接进入三条膨胀卷积分支，最后连同本地两源投影和 Base 条件一起聚合。这个原始 Detail 融合器没有递归状态。因此，不能把其信息损失称为已经定位的“状态记忆覆盖”。增加矩阵记忆是在尝试一种新解决方式，同时也引入了新的压缩与遗忘环节。

现有冻结 pilot 的原始结果支持两源传递不对称：光学候选传递从单源重建的 0.961 降至融合的 0.333；SAR 从 0.954 到 0.931。等输入 RMS 扰动下，逐图光学/SAR 增益比的平均值从投影层 1.210、多尺度分支 1.137，降至融合 Detail 的 0.906、最终图像的 0.572。原最大梯度目标在全有效区约 82.45% 由 SAR 提供。

这些是局部敏感性和候选结构证据：候选不是人工真值，单源重建同时使用 Base 与 Detail，监督比例也不是最终来源贡献率。它们支持检查聚合、监督和 Decoder 的共同适应，不能独自证明某种递归算子能解决问题。来源：[源路由原始结果](../test_result/e2_detail_route_localization_v1/val16_seed42/summary.json)、[Decoder 原始结果](../test_result/e2_fcsr_decoder_diagnosis_v1/val16_seed42/summary.json)。

还必须固定“E2”具体指哪个版本。上述诊断使用 `models/e2_scratch_original_loss_pilot_v1/seed42/epoch_016.pth`，即从头训练、光学 Base 保留的 `lwpd_e2_base_anchor_v1`。它与历史 R3 初始化的 `lwpd_e2` 不是同一个完整模型。新候选优先沿用这个 pilot 的结构、manifest 与 4 轮重建 + 12 轮融合预算，复用已有匹配对照；不能把光学 Base 改动、初始化差异一起归给 GDN2。

**对 DS-GDN2 设计，需要修正四个承诺。**

1. **分别存储状态，不等于整网来源隔离。** `lwpd.py::_gates` 的 optical/sar cross gate 都读取两源上下文；因此 `Do` 本身已受 SAR 条件调制。后续只用 `Do` 更新光学状态，可以保证另一源 value 不直接写入该记忆，但不能保证该状态对原始 SAR 输入的导数为零。保留 E2 时，宜称“LWPD 后源别分账的记忆”，不要称整条路径不存在跨源影响。
2. **状态分开，最终输出仍可能偏向 SAR。** 两路共享 Base 查询、输出归一化、聚合和 Decoder 都可能形成偏向。共享参数本身不等于共享状态，也不必自动改成两套完全独立参数。应明确哪些参数共享，并单独记录两路状态及最终来源响应。
3. **不使用和为 1 的 Softmax，不保证有效互补。** E2 原有 Detail 聚合本来就不采用两源 Softmax 竞争。改用独立门只是允许两路同时开或同时关，也可能同时放大伪影；不能把“去掉 Softmax”作为相对 E2 的主要新贡献。
4. **新颖性要落在融合行为上。** 独立擦写规则属于 GDN2 原论文；双分支递归与跨模态记忆也有已有工作。贡献应是具体的源别状态组织、读取与成图方式及其验证，而不是直接把已有算子换进 E2 再命名。此次有限检索不能认证“首次用于光学—SAR”。

**最需要修改的是消融设计。**

原材料只比较 Dual-GDN 与 Dual-GDN2，会同时改变衰减粒度、门控粒度及擦写是否独立，无法把差值归因于“解耦”。KDA 应进入直接机制对照。GDN2 最新 v2 的附录 H.1 还给出了更严格的共享向量门控制，保留两个门投影，只把它们的输出绑定；这个思路可以直接借鉴到本项目。[v2 附录 H.1](https://arxiv.org/html/2605.22791v2#A8.SS1)

| 对照 | 状态组织与更新 | 能回答什么 |
|---|---|---|
| 已有 E2 | 原多尺度卷积融合 | 固定性能参照，优先复用，不默认重训 |
| Dual-Conv | 同接口、近似参数量的两源普通上下文分支 | 收益是否主要来自容量、局部处理或新增残差 |
| Dual-KDA | 两源独立状态；逐通道衰减；擦写共用标量 | 相比成熟的逐通道 Delta 记忆有无额外收益 |
| Dual-GDN2-tied | 保留逐通道衰减及两个门投影，只绑定门输出 | 排除向量化、参数量等因素，检验擦写独立性 |
| Dual-GDN2 | 同样接口与状态规格，擦写门独立 | 核心候选 |
| Joint-GDN2 | 相同更新规则，共享状态；输入投影、读出和扫描尽量匹配 | 检验状态分账，避免用更换骨干解释“来源隔离” |

当 `d_k=d_v` 时，可令两个门投影给出的 sigmoid 输出为 `b`、`w`，在 tied 版使用 `g=(b+w)/2`，并令擦除门和写入门都取 `g`；独立版仍分别取 `b`、`w`。应保持两套投影及相同门范围、归一化、状态大小和读出方式。这个控制比只加 Dual-GDN 更接近拟检验的变量。

Joint-Mamba/Dual-Mamba 可以作为扩展骨干比较，但不应取代 Joint-GDN2、Dual-KDA 和 tied 版。联合/独立状态比较还要报告总状态元素数：两路状态如果各自与单路一样大，总容量就增加了。参数量、状态预算、序列长度、扫描路径和实际成本不能只用“近似参数相同”一笔带过。若采用两源 token 交替写入，必须说明 token 数和扫描邻接随之变化的限制。

**工程上，先保住 E2 的有效输入路径，再考虑完整替换。**

建议首个候选保留原本地 Detail 聚合为成图路径，用两源矩阵记忆提供受限的残差上下文。此时研究的是记忆能否补足原融合器；通过后再检验是否值得完全替换。所有卷积、tied 和独立门控制都必须采用同一个外部接口，避免残差框架成为额外变量。

对于 256×256 特征，先取得 128×128 的有符号 LH/HL/HH，将三子带按通道组织，并明确后续投影与符号处理；序列优先用行、列正反向，逐行/列重置状态、逐位置读取。行列独立扫描不能直接宣称每个位置已获得任意二维全局上下文。扫描方向、转置、反向恢复及子带布局都需要在小尺寸上检查。

这个选择主要用于避免已知错误：旧 `pac_mamba.py` 对完整重建 Detail 做对齐 2×2 平均池化，已有单图结果中两源池化后 RMS 分别仅约 `1.90e-10`、`1.38e-9`，替换为零输入的更新相对差约 `1.60e-7`。它说明旧 PAC 的目标高频入口几乎被抵消，不能用旧 PAC 的结果认定有效 Detail 输入下的递归建模已经失败。相应有符号路径在 `e2_phase_guide.py`、`e2_fsc_mamba.py` 中已有实现思路，应复用并核对，而不是重走平均池化入口。[已保存的抵消结果](../test_result/pac_input_cancellation_v1/single_scene_20261117/summary.json)

另外，`lwpd.py` 当前在内部计算门控后的高频子带，再逆变换成 `Do/Ds`；它没有直接把高频子带作为默认返回接口。若再次对 `Do/Ds` 做 Haar，必须保持同一算子、网格和边界处理，并核对与原门控子带的一致性；不能悄悄重新取未门控的高频而改变第一机制。

本轮只查询包元数据，当前 `.venv` 为 Windows、Python 3.8.10、PyTorch 2.4.1，未安装 `triton`、`triton-windows`、`flash-linear-attention` 或 `fla-core`。作者当前 requirements 固定 `torch==2.9.0`，Dockerfile 使用 `pytorch/pytorch:2.9.0-cuda12.8-cudnn9-devel`；FLA 也已有 GDN2 层。因此问题不是没有现成实现，而是现有项目环境并非作者验证环境，尚未证明可以直接运行。[官方依赖](https://github.com/NVlabs/GatedDeltaNet-2/blob/main/requirements.txt)、[Dockerfile](https://github.com/NVlabs/GatedDeltaNet-2/blob/main/Dockerfile)、[FLA 实现](https://github.com/fla-org/flash-linear-attention/blob/main/fla/layers/gdn2.py)

优先为高效实现准备隔离环境并固定版本，不直接升级当前 E2 环境。纯 PyTorch 逐步递推适合验证小尺寸前向、梯度及退化关系；没有 chunkwise/高效后端前，不据此安排完整图像训练或宣称速度优势。线性于序列长度不代表常数成本低，双源、四方向、矩阵状态均会增加实际开销。本轮没有安装或验证任何新后端。

**EDA 与 KLA 的位置。**

EDA 可保留为第二阶段理论备选。原材料的 `Erase + Write` 是示意式，不能充当忠实实现：原文规定先衰减、再独立地址擦除、再执行标准 Delta 纠正写入，算子顺序会影响结果。尤其不能把一个地址直接解释成“光学长期结构”、另一个解释成“SAR 新证据”。两源是同一场景的不同观测，空间扫描并不天然带有语言中事实更新的新旧关系。当前没有“地址冲突”证据，先接 EDA 会扩大待验证假设。[原文 §3.3](https://arxiv.org/html/2606.26560v1#S3.SS3)

KLA 暂缓。它提供的是建模假设下的状态估计与不确定性，迁移后需要证明表征观测模型成立；对 SAR/光学的差异也不能简单套用同强度标量的创新量。低位深图像与学习特征中的方差不能直接称物理散斑方差。作者实现还明确区分并行训练和常数每 token 解码，不能把“Linear Attention”一律表述成所有训练路径严格线性。[会议原文](https://proceedings.mlr.press/v306/shaj26a.html)、[作者实现](https://github.com/vaisakh-shaj/kalman-linear-attention)

Mamba-3 不优先是当前研究问题下的成本判断，不是其能力较弱的证据。若最终要比较递归骨干，在相同有效输入、扫描与读出条件下加入即可。Vision-LSTM、Vision-RWKV 同样先作为扩展参照，不并行启动多套迁移。

**建议按准入顺序投入实验，而不默认启动全表训练。**

1. 先只做实现准入：小尺寸验证有符号输入非零、扫描位置正确、前向与梯度有限、绑定标量门后能退化到 KDA/GDN。源隔离探针应在固定 LWPD 输出后分别干预两源，验证“无跨源直接写入”；原始图像级探针另报，不能混淆二者。合成记忆探针只能检查算子行为，不能作为融合收益证据。
2. 后端与数值通过后，先只训练一个新增 Dual-GDN2 pilot，采用匹配 E2 的 train1024/val64、4+12 轮、seed42、原损失和相同 Base/Decoder 结构，从头初始化整套模型。训练预算相同是公平筛查，不保证对新算子已充分优化；若后续单独调参，需重新说明成本与可比性。
3. 只有最终图像出现值得继续的联合收益，再依次补 Dual-Conv、tied 门、Dual-KDA；要主张来源分账有独立贡献，再补 Joint-GDN2。新模型不加载历史 E2/R3 权重；已有匹配 E2 对照继续复用。冻结 E2 的插值探针只作诊断，也不能代替联合训练。
4. 若候选只提高记忆读出或全图信息分数，未改善光学困难结构，或改善来自压掉 SAR 独有目标，不进入 EDA/KLA 扩展。当前也已有 RCT 结果说明微弱预测信号没有自动转成可见结构收益；这个限制仍适用于新记忆模块。[RCT 审查](RCT_预测增量与成图结果分析_20261118.md)

通过标准应在查看新结果前固定：光学困难边与源候选传递改善，同时记录 SAR 独有边、孤立目标、共同边及断开负例；QAB/F、FMI、VIF 与伪影指标联合审查，完整报告 SCD、SSIM、MS-SSIM 等 14 项。NAB/F 改善不能直接解释成去除真实散斑，门值也不能解释成结构真值。没有现成依据时不在此指定看似精确的容许退化阈值。

评价统一采用 `reference_v2_candidate_with_paper_fmi`，每项指标使用方法间共同有限场景，保存逐图值与样本数；新结果使用唯一目录并登记 `EXPERIMENT_REGISTRY.json`，只有完全相同 `comparable_group` 才合表。逐图配对区间与训练种子稳定性分开解释，val64 是反复使用的开发集。出现清晰信号后再做种子确认、固定配置的大规模验证和最终测试，不预设一整套基线重训。

本次交付是文献核验与接入建议，尚无新的训练入口，故不提供虚构的运行命令。本轮未新增实验结果，不修改注册表或生成索引。

**推荐的研究表述：在固定 LWPD E2 分解和监督下，源别分账的增量记忆及独立擦写，能否比同容量普通上下文与耦合记忆更好地将两源有效结构传递到最终图像？**

这个问题值得验证。现有证据还不足以将其写成“通过受保护记忆解决 SAR 覆盖”，或将 GDN2 预先确定为有效的第二创新点。
