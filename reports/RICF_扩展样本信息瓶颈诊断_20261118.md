# RICF 信息瓶颈诊断：扩展至 train128 / val64

状态：仅实现脚本，**没有运行真实 QXS-SAROPT 推理，不能据此声明扩样本结果已产生**。

## 为什么扩大样本

已有冻结 E2 的 train8/val16 实验中，PCA64 的源 Detail 线性恢复误差显著小于原 E2 fused Detail，且 PCA64 保留 99.19% 的训练方差。但 8 张训练图不足以确认 PCA 投影在多场景上稳定，16 张验证图也无法充分评估离群场景和 SAR 散斑场景差异。

新版采用同一匹配 pilot manifest（train1024/val64）：

- 默认从 train1024 **均匀取 128 张**，计算训练统计量、PCA、线性 ridge probe；
- 使用 **全部 val64** 做独立验证，不读取 test；
- 可选 train256/val64，取样政策与验证定义不变；
- 训练图按场景流式累计标准化统计、CCA/PCA 协方差及岭回归充分统计量，不在内存累计全部图像特征；需要三轮冻结模型提取，但**不反向传播、不进行模型训练**；
- 固定 E2 checkpoint、stride=4、ridge=0.01、五种基线均不改。

训练拟合总共三次读取训练场景：标准化均值方差、PCA 协方差、ridge 回归正规方程。数学目标与旧版在浮点误差范围内一致，CPU 合成单测检查流式结果对照整批拟合结果。新脚本不会覆盖旧结果。

## Windows CMD（仓库根目录）

```cmd
cd /d "D:\#imageInfusion\CDDFuse"
git pull --ff-only origin main
.venv\Scripts\python.exe -m unittest -v test_ricf_bottleneck_expanded
.venv\Scripts\python.exe diagnose_ricf_bottleneck_expanded.py
```

默认 train128/val64。扩大训练数据用：

```cmd
.venv\Scripts\python.exe diagnose_ricf_bottleneck_expanded.py --train-scenes 256 --val-scenes 64 --output-dir test_result\e2_ricf_bottleneck_expanded_v1\train256_val64_seed42
```

若需严格检验“仅扩大验证集”的作用，使用相同的初始8张训练图（原版 train8）+ val64：

```cmd
.venv\Scripts\python.exe diagnose_ricf_bottleneck_expanded.py --train-scenes 8 --train-selection first --val-scenes 64 --output-dir test_result\e2_ricf_bottleneck_expanded_v1\train8_val64_seed42
```

**注意：** 不应将 train8/val16 与 train128/val64 的误差差异全部归因于验证集扩大；两者训练探针时使用的场景数不同。

## 输出

test_result/e2_ricf_bottleneck_expanded_v1/train128_val64_seed42/：

- recoverability.csv：64张逐图、五个表示、两种模态的 NMSE / R²；
- edge_residual_proxy.csv：同图高低梯度区域的线性恢复误差，仅为弱代理；
- summary.json：PCA解释方差、逐模态恢复均值、PCA 对 E2 的胜出图像数和误差比、中位数、去除顶部10%离群值的 E2 NMSE、输入场景及校验哈希。

## 继续 / 停止 RICF 的判断

**必要但不充分：** PCA64 的恢复优势需在 val64 中广泛成立，且不能只靠少量异常图推动均值。检查光学/SAR分开结果、高低梯度区域表现及样本训练量增大后的稳定性。

**关键限制：** PCA 直接以两源 Detail 的方差保留为目标，而 E2 以最终融合图为目标；即使 PCA 在所有64图上恢复得更好，仍不足以证明 E2 丢弃的是有效结构，亦不保证 RICF 可改善融合图的 QAB/F、NAB/F、FMI 或 VIF。需要单独的图像级、参数量匹配的融合对照才能决定训练 RICF。
